# HuntReplay Studio

**Автономный Windows-клиппер для Hunt: Showdown 1896 и совместимых 64-битных игр с NVIDIA Highlights.**

.NET 8 / WPF • Windows Graphics Capture • Direct3D 11 • WASAPI • AMF / NVENC / QSV

Новый проект находится в `src/` и `native/`. **Он не использует OBS, Streamlabs,
Python, горячие клавиши драйверных рекордеров или отдельный ffmpeg.exe.** FFmpeg —
встроенные библиотеки, а не внешнее приложение записи. Сжатые пакеты до сохранения
находятся в RAM, а не во временных видеофайлах на SSD.

> **Статус: pre-release 0.1.3, не сертифицированный Windows-релиз.**
> [Windows и Ubuntu CI прошли для коммита `7a5aacf`](https://github.com/Mlovo/HuntOpenHighlights/actions/runs/37931206688):
> Набор Core/IPC/view-model/библиотеки (**117 тестов**, Ubuntu и Windows, код выхода 0) и **22 WPF-регрессии**;
> MSVC native build и публикация self-contained .NET 8/WPF EXE. Счётчик 117 — из локального запуска того же кода,
> лог job недоступен из песочницы. Физические WGC/WASAPI, AMF/NVENC/QSV,
> UAC, Hunt/EAC и запрос рамки на Windows ещё требуют [аппаратной проверки](docs/WINDOWS_VALIDATION.md).
> Успешная компиляция не подтверждает работу на каждой видеокарте или одобрение античита.
> Подробности и границы проверки: [VALIDATION.md](docs/VALIDATION.md).

## Что реализовано в исходниках

- **Первый запуск:** установка оригинальной `MessageBus.dll` из встроенного ресурса;
  SHA-256 + Authenticode/NVIDIA signer; отдельный UAC-процесс; резервная копия
  изменяемых значений HKLM; проверка конфликтов; восстановление без удаления чужих
  веток NVIDIA. Сам GUI и рекордер не требуют запуска от администратора.
- **Захват:** WGC окна Hunt / выбранного монитора → GPU BGRA→NV12 → аппаратный
  FFmpeg-энкодер. Auto выбирает AMD AMF, NVIDIA NVENC или Intel QSV по адаптеру
  дисплея. CPU x264 включается **только явно**. 30/60/120 FPS, H.264/HEVC/AV1,
  битрейт 10–80 Мбит/с и GOP 1/2 секунды.
- **Звук:** WASAPI loopback, опциональный микрофон, нормализация к 48 кГц,
  синхронизация по QPC, AAC; стереомикс либо отдельная микрофонная дорожка.
- **RAM-буфер:** временной и жёсткий байтовый предел, удаление целыми GOP,
  удержание пакетов незавершённой серии, неизменяемые snapshots, ограниченная
  очередь экспорта. При нехватке данных сокращение клипа явно отмечается.
- **События:** реальный `NvMessageBusBroadcast`, big-endian framing и генерация
  C# по существующим `.proto`; JOIN/NvNode, авторизация scopes 1–7, конфигурация,
  группы, видео-триггеры, keep-alive, разрешения и конфигурация событий.
- **Multi-kill:** события с промежутком до 15 секунд объединяются. Ожидание
  следующего фрага отделено от конца видео: по умолчанию клип заканчивается
  через 7 секунд после последнего события, а не через 15.
- **Lossless trim:** начало по игровому `startDelta` / заданной предзаписи,
  округление назад до ключевого кадра, прямой MP4 mux/stream copy. Повторного
  кодирования и анализа движения изображения нет.
- **WPF UI:** тёмный dashboard, реальные статусы и расход RAM, живой журнал,
  настройки всех разделов, галерея с FFmpeg-превью, Windows-плеер с Play/Pause/seek,
  переименование, удаление, открытие папки, диагностика, трей, ручной хоткей F1–F12 (по умолчанию F9),
  звук и Windows Toast. Пустая галерея не заполняется демонстрационными клипами.
- **Автоматика:** HKCU-автозапуск в трей, поиск `Hunt.exe` / `HuntGame.exe` /
  `HuntGameSteam.exe` и окна подключившегося SDK-клиента; остановка с игрой,
  ограниченные повторные запуски после ошибок устройства.
- **Хранилище:** атомарный `config.json`, collision-safe имена, MP4 + sidecar,
  opt-in очистка только собственных клипов. Чужие видео не удаляются.

## Сборка одного переносимого `.exe`

**На машине разработчика:** Windows x64, .NET SDK **8.0.4xx или новее в ветке 8.0**,
Visual Studio 2022 / Build Tools с **Desktop development with C++**, Windows SDK
10.0.22621+ и CMake 3.25+ в PATH. Для первого restore/download нужен интернет.
На компьютере игрока эти инструменты не нужны.

```powershell
# Из корня репозитория, обычный (не административный) PowerShell:
powershell -ExecutionPolicy Bypass -File .\tools\Build.ps1
```

Результат: **`artifacts\publish\HuntReplayStudio.exe`**.

Скрипт сверяет исходную DLL NVIDIA, скачивает **зафиксированный по SHA-256** shared
SDK FFmpeg только на этапе сборки, создаёт MSVC import libraries, компилирует
нативный движок, запускает тесты, встраивает DLL и публикует .NET/WPF self-contained.
При запуске приложение извлекает проверенные ресурсы в пользовательский кэш.
Отдельная установка .NET, VC++ Redistributable, FFmpeg или рекордера не требуется.

Подробности: **[BUILD_WINDOWS.md](docs/BUILD_WINDOWS.md)**.
Перед публичным распространением: **[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)**.
Подписана исходная NVIDIA DLL, **не автоматически ваш новый `.exe`**.

## Первый запуск на игровом ПК

1. Windows 10 **2004 / build 19041+** или Windows 11, x64; рабочий D3D11 GPU и
   актуальный драйвер с нужным энкодером. Для воспроизведения нужен Windows media stack.
2. Откройте `HuntReplayStudio.exe`. В мастере нажмите **«Установить и продолжить»**
   и подтвердите UAC. Отказ от UAC оставляет доступ к ручному захвату монитора.
3. Если найдена существующая регистрация NVIDIA, замена требует отдельного согласия.
   Не запускайте параллельно старый Python-сервер / другой сервер Highlights.
4. Проверьте **«Диагностика → Проверить готовность системы»**. Проба действительно
   кодирует тестовые GPU-кадры; наличие названия энкодера не выдаётся за поддержку GPU.
5. Запустите Hunt. По умолчанию буфер стартует при появлении окна игры. Рабочий
   стол при отсутствии игры **не** становится источником автоматически.
6. Игра должна отправлять NVIDIA Highlights; если она предоставляет переключатель
   Highlights в настройках, включите его. Убийства/ноки будут передаваться в Studio.
   Для ручного клипа нажмите **F9** или кнопку dashboard. Ни `Ctrl`, ни `Shift`,
   ни `WASD` приложение не отправляет.
7. По умолчанию клипы: `%USERPROFILE%\Videos\HuntHighlights` (через Windows Known
   Folder, поэтому перенесённая папка «Видео» учитывается). Закрытие окна прячет
   приложение в трей; **полный выход — через меню в трее**.

### Где находятся данные

| Данные | По умолчанию |
|---|---|
| Настройки | `%LOCALAPPDATA%\HuntReplayStudio\config.json` |
| Логи, локальные, с ротацией | `%LOCALAPPDATA%\HuntReplayStudio\logs\` |
| Извлечённые нативные DLL | `%LOCALAPPDATA%\HuntReplayStudio\runtime\<manifest-hash>\` |
| Установленная SDK-шина | `C:\NvidiaShim\MessageBus.dll` |
| Резервная копия реестра | `%PROGRAMDATA%\HuntReplayStudio\shim-installation.json` |
| Клип | `*.mp4` в папке клипов (по умолчанию `%USERPROFILE%\Videos\HuntHighlights`) — только видео |
| Метаданные и превью клипов | `%LOCALAPPDATA%\HuntReplayStudio\library\records\<Id>.json` и `…\library\thumbs\<Id>.png` |

`--portable` размещает **настройки, логи и библиотеку клипов** (`library\`) рядом с exe
(папка должна быть доступна для записи). HKLM-регистрация шины всё равно системная, а нативный кэш — per-user.
`--tray` запускает свёрнутым. Старый корневой `config.json` относится к Python и
новым приложением **не читается**.

## Важные технические границы

- «Любой производитель GPU» не означает поддержку AV1/HEVC на любой старой карте.
  Нужны соответствующие аппаратные блоки и драйвер. Auto не скрывает ошибку за x264.
- **Нет обещания <1% CPU**, постоянных 120 FPS или определённого времени сохранения:
  GPU-конверсия, аудио AAC, копирование сжатых пакетов, UI и диск имеют стоимость.
- **Нет гарантии EAC / отсутствия санкций.** В коде нет инжектов, чтения памяти
  игры, подмены GfeSDK или эмуляции ввода; это описание архитектуры, не одобрение
  разработчика игры/античита. Сверяйтесь с актуальными правилами.
- Эта версия записывает **SDR, 8-bit NV12**. HDR/tone mapping не реализованы.
  При resize источник масштабируется в canvas текущей сессии; Native-размер
  пересчитывается при следующем старте буфера.
- Loopback пишет **весь звук выбранного endpoint**, не изолированный процесс.
  Микрофон выключен по умолчанию. Смена default endpoint обнаруживается;
  при ошибке запись останавливается с логом и ограниченным авторестартом.
- Windows `MediaElement` воспроизводит H.264 штатно при наличии media stack.
  **HEVC/AV1 в плеере могут требовать системных декодеров/расширений Windows**;
  их отсутствие не мешает нативному кодированию, mux и FFmpeg-превью. Это ограничение
  встроенного плеера данной версии, а не скрытая зависимость записи от OBS. Ошибка
  открытия (`0xC00D11B1`, общий `NS_E_WMP_FILE_OPEN_FAILED`) сама по себе не называет
  причину: клип при этом сохранён и не изменён, его можно открыть кнопкой
  «Открыть в проигрывателе», а для новых клипов выбрать H.264.
- **Жёлтая рамка WGC** остаётся, если Windows не выдала согласие. Studio при старте записи
  официально запрашивает захват без рамки (`RequestAccessAsync`, Borderless, таймаут 3 с).
  Официальный путь выдаёт согласие только упакованному приложению с capability
  `graphicsCaptureWithoutBorder` и решением пользователя; portable EXE его не получает.
  Studio не меняет реестр, не обходит индикатор и не обещает исчезновения рамки; запись
  продолжается, причина пишется в лог. См.
  [VALIDATION.md, раздел 5](docs/VALIDATION.md#5-жёлтая-рамка-wgc-официальные-условия).
- Интерфейс NVIDIA overlay, screenshots, OPS-оптимизация и encrypted IPC не
  реализуются: сервер явно отказывает в неподдерживаемых SDK-операциях.
  Это совместимый **video Highlights backend**, а не полная NVIDIA App.
- 60 с × 25 Мбит/с ≈ **179 МиБ сжатого видео**, плюс аудио/метаданные, runtime и
  GPU surfaces. Во время серии RAM может временно увеличиваться. Метка RAM в UI
  показывает сжатые пакеты, а не полный working set процесса.
- Галерея показывает до 500 последних клипов, записанных Studio. MP4 без записи
  библиотеки (например, скопированный с другого ПК) не импортируются и не участвуют в
  очистке. Клипы версии 0.1.2 переносятся в библиотеку при первом обновлении галереи.
  Метаданные больше не лежат рядом с MP4, поэтому при переносе самой папки клипов на
  другой ПК без библиотеки клипы в галерее не появятся. Незавершённые `.partial.mp4`
  после аварийного выключения также не удаляются автоматически.

### Сохранённая Python-база

Оригинальные `server.py`, `recorder.py`, batch/VBS-файлы и `requirements.txt`
оставлены для истории и сравнения протокола. Они **не являются частью Studio**
и не попадают в exe. [Старая инструкция](docs/LEGACY_PYTHON.md) описывает прежний
OBS-прототип, включая его непроверенные заявления о безопасности; это не
инструкция для нового приложения. Не используйте legacy `uninstall.bat` для
удаления Studio: он не знает о новой резервной копии и удаляет слишком широкие
ветки. Используйте кнопку восстановления в диагностике.
